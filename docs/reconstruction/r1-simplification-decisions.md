# R1 Simplification Decisions

This file freezes R1 product decisions so later phases do not reintroduce removed complexity by accident.

## Keep as primary everyday capabilities

- Open/read/search PDF
- Edit existing text
- Add/edit images and text
- Highlight/comment/draw
- Visual signature
- Redaction
- Pages: reorder, rotate, duplicate, delete, extract, merge, split, crop
- Compress/optimize
- OCR
- Fill forms
- Password protection
- Images/camera to PDF
- Common PDF exports
- Project backup/recovery

## Keep, but behind progressive disclosure

- Vector editing details
- Table reconstruction details
- Nested Form XObject manipulation
- Stamps and advanced object layout
- Advanced OCR preprocessing
- Metadata editing
- Watermark/header/footer/page-number controls
- Grayscale conversion
- Batch automation
- Compare
- Bates numbering
- Print imposition
- Optional-content layers
- DOCX text export
- Standards/preflight
- PDF/A candidate preparation
- Accessibility inspection/repair
- Signature inspection
- Repair PDF
- Document structure inspection
- Download history

## Merge into canonical workflows

- All metadata-removal entry points
- Security/structure/preflight inspection surfaces
- Archive readiness checks
- Print-imposition implementations
- Lossless/structure-safe optimization variants
- Toolbox container
- Forms & Protect container
- Print & Advanced container
- Accessibility container where it duplicates Forms/Signatures
- Local storage health into Troubleshooting
- Simple/Advanced global mode concept into task-based progressive disclosure

## Hide from ordinary product surfaces

- Engineering diagnostics laboratories
- App release self-check
- Native capability confidence percentages
- Legacy native-editor compatibility route
- Preservation structure graph
- Detached signature evidence except technical details
- Certificate-backed signing until a real signer integration exists
- High-fidelity Office conversion until a real engine exists

## Remove from product exposure

- P-phase labels and implementation-phase terminology
- Legacy Professional text editing
- Legacy Professional image replacement
- Standalone Preservation mode
- Duplicate Home PWA-readiness card
- Home engineering-foundation marketing cards

## Repair before mature exposure

### Command palette
Must become task/action search rather than workspace-mode search.

### Workspace navigation
Must move from subsystem taxonomy to user intent.

### Context suggestions
Must never recommend technical inspection simply because a document lacks an outline.

### Editor object list
Must remove native/overlay/confidence/z-index implementation vocabulary from normal view.

### Form authoring
Must reconcile the Compliance field creator with the Secure workspace's stated capability boundary and receive dedicated export/reopen/cross-reader qualification.

## Do not delete engines merely to simplify UI

R1 is an exposure audit. Internal implementations may remain temporarily when they:

- preserve backward compatibility;
- serve a better canonical workflow later;
- are required by migrations/checkpoints;
- provide useful validation or support evidence.

Deletion of internal code must follow dependency and migration analysis. UI removal does not require immediate engine deletion.

## Anti-regression rule

After R2, no new top-level mode/container may be added unless all of the following are true:

1. it represents a distinct user intent rather than an implementation subsystem;
2. an existing canonical action cannot absorb it;
3. it has a truthful capability state;
4. it has a representative workflow test plan;
5. it materially improves completion time or clarity for the target audience.
