## Owner release and postrelease closure are distinct

\`reconcile_owner_release.py\` defines three separately signed
review stages with three **distinct real operator roles**:

- account owner: \`ownerReleaseReview\`, a source-bound **review request**,
  not authorization to publish;
- independent release operator: \`independentOperatorReview\`, evidence
  custody acknowledgment, never a merge or deploy instruction;
- recovery operator: \`postreleaseClosureReview\`, a separate later review
  that is neither pre-release authorization nor proof of postrelease success.

Stages require Ed25519 signatures verified against an externally pinned,
root-signed trust history with signer grant, cross-signed rotation,
revocation and compromise handling inherited from F13. No private keys
or actual human identities are generated by F15. Each signed stage
binds original F14 SHA, current exact F15 SHA, a single evidence manifest
SHA256, UTC issue/expiry, unique anti-replay nonce and signer counter;
closure cannot predate release-operator review.

Mandatory evidence objects, each requiring a safe original file path and
SHA256, include prior-stable release bytes, separately restored stable
bytes, encrypted backup, observed restore and rollback transcripts,
accessibility and physical mobile sessions, third-party reader/print
witness, and source/rights/privacy provenance. Previous-stable and
restored bytes must be **identical**, and both prior-stable bytes and encrypted
backup ciphertext must match **two independently supplied SHA-256 pins**
provided by an authorized off-CI operator. A backup ciphertext cannot be
substituted for stable release bytes. These pins cannot be inferred from the
same submitted evidence manifest. Without the external pins, signed review
claims fail closed. Byte equality and signatures
do **not** prove a real restore or witnessed drill; those real-world
facts require independent human custody and are marked unconfirmed.

Original witnessed mobile/physical/human claims pass through F14's
independently signed reviewer and separate witness verification at the
**original F14 source SHA**, not at the distinct current F15 head.
Those signatures still cannot be automatically treated as physical
acceptance or owner release approval.
